2. STORAGE CONTRACT  (corrected per coordinator 2026-10-08)
-----------------------------------------------------------
Firestore owns every contract the Node runtime kept there. Nothing was migrated
to new empty SQL tables.

  balances/{uid}                    availablePkn, lockedPkn, updatedAt
  ledger_entries/{id}               uid, type, amountPkn, counterpartyUid,
                                    counterpartyUsername, ref, ...meta, createdAt
  commerce_idempotency/{sha256}     replay guard (original key stored inside)
  native_pkn_deposits/{txHash}      uid, txHash, fromAddress, amountPkn, purpose
  withdraw_requests/{id}            uid, email, toAddress, amountPkn, status, ...
  pkn_purchases/{stripeSessionId}   Stripe PKN checkout credit record
  orders/{orderId}                  buyerUid, paymentStatus, status, items,
                                    shipments, totalPkn/totalEURCents, pknDiscount
  marketplace_sales/{id}            orderId, cardId, sellerUid, quantity, pricePkn
  money_requests/{id}               fromUid/fromUsername/toUid/toUsername/status
  notifications/{id}                uid, type, requestId, actorUsername, read
  users/{uid}, usernames/{username}, wallet_addresses/{...}
  users/{uid}/shipping_addresses/{id}   countryCode + AES-256-GCM envelope
  outbox/{id}                       queued email (no SMTP at request time)
  crypto_pkn_purchase_quotes|_requests|_deposits/{id}
  crypto_pkn_sale_quotes|_requests|_payouts/{id}
  wpkn_exchange_quotes|_requests|_deposits/{id}
  wpkn_exchange_config/reserves          availableLiquidityPkn,
                                         settlementWpknPkn, lockedPkn

Every money movement is one Firestore transaction (`store::apply`): read the
balance docs inside the transaction, apply the delta, then commit balance
writes + ledger entries + the idempotency marker together. A replayed key
returns the recorded result.

Postgres owns the marketplace read model, which already exists in scripts/sql
and is used as-is:
    READ  -> state.read_db()   (MARKETPLACE_DATABASE_URL, the Pi replica)
    WRITE -> state.write_db()  (MARKETPLACE_WRITER_DATABASE_URL, nezopt 15T)
marketplace_user_listings, marketplace_user_carts, marketplace_user_recents,
marketplace_checkout_holds, shipping_rates, marketplace_rate_limits,
marketplace_search_candidates, marketplace_cards, marketplace_card_versions,
marketplace_card_cart_*/watchlist_analytics, marketplace_card_events,
cardtrader_pokemon_blueprints.

SQL to apply:
    pokoin-rust/crates/commerce/sql/001_commerce.sql
This file creates NO new tables. It is a preflight check that the existing
marketplace read model is present plus two optional, re-runnable indexes on
existing marketplace tables. Target: the nezopt writer (and the Pi replica
already streams it). There are no wallet/user/ledger/order/quote tables.

ACCOUNTS WORKER INTERFACE:
    `store::LedgerOp` + `store::apply` are the seam. Balances/ledger live in the
    Firestore collections above; when pokoin-accounts lands it can back the same
    LedgerOp call sites without touching the handlers.

4. UNRESOLVED (do not claim these are done)
-------------------------------------------
* Crypto/wPKN quotes, requests, deposits, payouts and the exchange reserve
  snapshot now live in the Firestore collection names the Node writers used
  (`crypto_pkn_purchase_quotes|_requests|_deposits`, `crypto_pkn_sale_quotes|
  _requests|_payouts`, `wpkn_exchange_quotes|_requests|_deposits`,
  `wpkn_exchange_config/reserves`); no SQL quote tables remain.
* CardTrader: mirror push on listing create, live CT read merge on public card
  desks, CT buy-through on orders, CT link/import intents.
* Orders: mark_shipped / confirm_delivery / report_problem / reveal_address /
  cancel / refund / seller sold-history return 501 ORDER_ACTION_NOT_PORTED.
* EUR fulfilment after a paid Stripe session (ownership, linked CardTrader,
  seller emails, seller Transfers, native sold rows) is not ported; the webhook
  marks the order paid, validates the amount, consumes the held PKN discount
  and releases stock on expiry/failure.
* Payout signing is ported for both chains.
  EVM (`crates/commerce/src/evm.rs`): RLP + keccak256 + secp256k1 (k256),
  EIP-155 legacy transactions, used for Pokoin bank/reserve PKN, EVM native
  coins, ERC-20 transfers and wPKN settlement.
  Bitcoin (`crates/commerce/src/bitcoin.rs`): base58check, bech32/bech32m,
  HASH160, WIF keys, UTXO selection, conservative fee estimation and BIP143
  P2WPKH signing, broadcast to the configured explorer.
  Without a key the behaviour stays manual (`manual_pending` /
  `bitcoin_manual_pending`) exactly like Node; a key on the wrong network or a
  bank key whose derived address does not match the configured wallet fails
  before any request; a rejected broadcast is an error, never a fabricated hash.
  `assertPayoutLiquidity` is enforced both in the sale quote (409 before a quote
  larger than the measured payout liquidity) and immediately before signing.
  wPKN is the Pokoin-wrapped BEP-20 token rather than a `CHAIN_CONFIG` asset, so
  `send_wpkn` signs an ERC-20 transfer directly against the configured contract
  and checks the settlement key/address pair first.
* The only remaining 501 is the `ORDER_ACTION_NOT_PORTED` guard for an
  unrecognized `action` value on `/api/marketplace-orders`; every documented
  action is implemented.
* Satellite-game catalogs (24 TCGs) are wired through per-game pools
  (`<GAME>_MARKETPLACE_DATABASE_URL`, the Node `databaseUrlEnv` contract) for
  Recently Seen catalog validation and seller shops. When a game's URL is not
  exported the route answers 503 GAME_CATALOG_UNCONFIGURED (or
  GAME_CATALOG_UNAVAILABLE when the pool cannot be reached) instead of reading
  another game's rows. Marketplace events stay on the shared writer, matching
  the Node handler.
* Seller shop printed-rarity expression is approximated; associate badge, photo
  URL and cached-read layer are not ported.
* Chat conversation mirror for money requests (conversations/events) is owned by
  the chat worker.
* Outbound email is a Firestore `outbox` document; the delivery worker is not
  part of this crate.
